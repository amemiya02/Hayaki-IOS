# Hayaki for iPhone and iPad

A learner can take the same collection between Hayaki on Android and Hayaki on iOS, study offline, edit it and keep the resulting cards, scheduling, review history and media. Completion means the full Android feature set works through native iOS entry points. The [ticket inventory](ios-parity-tickets.md) assigns ownership for each area.

## Using Hayaki on iOS

- **Open and study.** Welcome offers the Android entry paths for starting empty, importing and syncing, using the active profile’s destination. Decks shows what is due and studied today. Opening a deck, revealing a card and rating it preserve the Android queue, counts, intervals and undo behavior. The finished screen explains when to return, including later learning, burying and daily limits. Filtered decks and custom study retain their distinct behavior.
- **Navigate and control study.** Decks, Browse, Stats and More are the four primary destinations. Use iPhone tabs and an adaptive iPad sidebar and split view. Keep a single reviewer. Preserve Android's available toolbar actions, gesture and key bindings, timers, template speech, recording, whiteboard and compatible card-script actions. Use native keyboard, controller, Pencil and touch input where available. Keep the content styled by its card template.
- **Create and maintain a collection.** Browse supports the Android searches, saved views, row modes, configurable columns, sorting, selection and bulk actions. Preserve the note editor, media tools, quick add, preview, image occlusion, note types, fields, template editing and conversion mappings. Verify changes by reopening the same notes and generated cards on Android.
- **Understand progress and scheduling.** All Android statistics, filters, presets, scheduling options and FSRS tools are available from native screens. Given the same collection, time zone, study day and filters, both apps must produce the same underlying values and saved options. Unedited settings survive a save.
- **Move and protect data.** A deck package merges. A collection package replaces after confirmation and a backup. Preserve supported import formats and options, export compatibility, shared decks, media checks, storage management, profile isolation and restore. Expose iOS Files, sharing and notification entry points for the equivalent Android actions.
- **Sync.** Each profile owns one destination for both collection and media. Keep existing self-hosted profiles on their chosen server. Match the Android sign-in, conflict, forced transfer, media progress, retry and cancellation outcomes. Never send credentials or queued work from one destination to another. Offer AnkiWeb as the new-profile default through the unmodified upstream sync implementation. Exercise self-hosted sync against a local server and verify hosted sync with a dedicated test account. [Android sync change](https://github.com/amemiya02/Hayaki/commit/0f5dc353fb424751d74ba7d315457b62d95348a7)
- **Use the app every day.** Include share-to-add, configurable deck widgets, deck reminders and their return destinations. Support system appearance and explicit Light, Dark and Black choices, locale-correct system typography and accessible semantic colors. English, Simplified Chinese and Japanese are first-class. Preserve applicable upstream translations and English fallback, and check an RTL layout. Keep analytics and automatic crash reporting off.

## Engineering and distribution

Build on the existing iOS 26+ project, Swift 6 packages, serialized collection access and unmodified pinned Anki core. The native interface includes statistics, deck options, card information, importers, change-note-type mappings and image occlusion. WKWebView renders template content in the reviewer and previews. Preserve the existing source-build and device-install workflow. The app ID, licensing and core build decisions carry forward. [Core architecture](../adr/0001-embed-ankis-rust-core.md) · [Platform decision](../adr/0005-android-parity.md) · [Build and installation](../../README.md)

Kioku provides a comparison for studying and browsing on a phone, touch and keyboard behavior, and finding exports in Files. Its iOS build embeds the desktop Python/Qt application and adapts its web views to WKWebView. Desktop add-ons and Kioku's distribution channels are specific to that product. Hayaki's acceptance target is the Android baseline above. [Kioku iOS implementation](https://github.com/krmanik/kioku/blob/7f5fe5b5d1b13724bccfb5dc0fa8443111e63d1e/ios/README.md)
